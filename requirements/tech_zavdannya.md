# Спрощене технічне завдання (ТЗ): Система обліку оренди обладнання

## 1. Мета і завдання продукту

**Мета продукту:**
Створити єдину веб-орієнтовану систему для автоматизації процесів здачі техніки та обладнання в оренду, що дозволить мінімізувати ризики втрати чи подвійного бронювання інвентарю та забезпечить прозорий контроль за його рухом.

**Основні завдання:**
* Забезпечити безперервний облік наявного обладнання та його поточних статусів у режимі реального часу.
* Спростити та автоматизувати процес бронювання техніки для клієнтів із попереднім прорахунком вартості.
* Надати зручні інструменти для роботи персоналу (менеджерів) під час видачі, повернення та фіксації технічного стану обладнання.
* Реалізувати рольову модель доступу (Адміністратор, Менеджер, Клієнт) для безпечного управління даними системи.

## 2. Загальні функціональні та нефункціональні вимоги

### Функціональні вимоги:
1. **Каталог обладнання:** Користувач може переглядати список доступного обладнання з можливістю фільтрації за категоріями (наприклад, "електроінструмент", "будівельна техніка") та статусом ("вільно", "в оренді").
2. **Бронювання:** Користувач (Клієнт) може обрати вільне обладнання та надіслати запит на бронювання, вказавши дати початку та завершення оренди.
3. **Управління статусами:** Користувач із роллю "Менеджер" або "Адміністратор" може змінювати статус обладнання на "Вільно", "В оренді" або "На обслуговуванні".
4. **Калькуляція вартості:** Система повинна автоматично розраховувати загальну вартість оренди на основі кількості днів бронювання та добового тарифу обраного обладнання.
5. **Авторизація:** Користувач може зареєструвати обліковий запис та увійти в систему, використовуючи електронну пошту та пароль.

### Нефункціональні вимоги:
1. **Швидкодія:** Час завантаження першої сторінки каталогу обладнання (до 20 карток) не повинен перевищувати 2 секунди за умови стандартного 4G/Wi-Fi з'єднання.
2. **Кросбраузерність (Compatibility):** Веб-інтерфейс повинен підтримувати повний функціонал та коректно відображатися без візуальних дефектів у трьох останніх стабільних версіях браузерів Google Chrome, Safari та Mozilla Firefox.
3. **Безпека:** Паролі всіх користувачів (клієнтів, менеджерів, адміністраторів) повинні зберігатися в базі даних виключно у захешованому вигляді (наприклад, з використанням алгоритму bcrypt).
4. **Надійність обробки даних:** Система повинна успішно обробляти одночасні запити на бронювання одного і того ж обладнання, гарантуючи, що його зможе орендувати лише перший клієнт, уникнувши подвійного бронювання.
5. **Масштабованість:** Система повинна стабільно працювати та обробляти запити без зниження продуктивності при одночасному підключенні до 100 активних користувачів.

## 3. Обмеження

1. **Технологічні обмеження:** Продукт реалізується виключно як веб-додаток. Доступ до системи потребує постійного підключення до мережі Інтернет.
2. **Організаційні обмеження:** Розробка ведеться однією особою (без залучення команди тестувальників чи додаткових розробників), що обмежує ресурси на реалізацію складного додаткового функціоналу на етапі MVP.
3. **Функціональні обмеження (на етап MVP):**
    * Система не має інтеграції з банківськими платіжними шлюзами; оплата оренди фіксується поза межами цієї системи.
    * Відсутня інтеграція з апаратними сканерами штрих-кодів для видачі техніки (пошук здійснюється вручну через інтерфейс).

## 4. Очікувані результати

По завершенню розробки очікується отримання наступних результатів:
1. **Робочий веб-додаток (MVP)**, який можна розгорнути на сервері для демонстрації та використання.
2. **Спроєктована база даних**, що здатна зберігати інформацію про користувачів, каталог обладнання та історію транзакцій (оренд).
3. **Реалізований ключовий сценарій (User Flow):** клієнт успішно реєструється, знаходить вільну техніку, бронює її; менеджер підтверджує видачу, а згодом — повернення обладнання, змінюючи його статус.
4. **Репозиторій на GitHub** із вихідним кодом проєкту та інструкцією для його запуску (README).

## 5. Стек технологій (MVP)

Для забезпечення швидкої розробки, масштабованості та зручного розгортання системи обрано наступний стек:

**Фронтенд (Клієнтська частина):**
- **Бібліотека / Збірка:** React у зв'язці з Vite для швидкого старту та оптимізації роботи.
- **Стилізація:** Tailwind CSS для оперативного створення сучасного, адаптивного інтерфейсу без написання громіздких CSS-файлів.

**Бекенд (Серверна частина):**
- **Середовище та фреймворк:** Python + FastAPI для швидкої розробки API.
- **База даних:** MongoDB (з використанням хмарного кластера MongoDB Atlas) для гнучкого зберігання каталогу, користувачів та історії оренд.

**Інфраструктура, розгортання та інструменти:**
- **Хостинг:** Render або Railway для швидкого та безкоштовного розгортання веб-додатка на етапі тестування.
- **Контроль версій:** Git з розміщенням репозиторію на GitHub.
- **Середовище розробки:** WebStorm для написання та відлагодження коду.
